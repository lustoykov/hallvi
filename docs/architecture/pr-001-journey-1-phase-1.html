Architecture · PR #1 · Journey 1 Phase 1

One Next.js process owns the launch brief

Phase 1 is a full-stack Next.js modular monolith. The operator UI sends commands to Route Handlers; domain logic validates them, records the Operator Record in SQLite, and calls GitHub or a deliberately isolated Pi session through narrow adapters.

Flow 01 · Create launch workspace

A fixed command creates the record, then observes GitHub

A repeat with the same permission policy is idempotent. A conflicting policy returns an explicit conflict instead of silently changing authority.

One process

No FastAPI service or worker yet

UI, HTTP routes, domain rules, adapters, and persistence run in one Next.js Node.js process. Phase 1 has no requirement that justifies a second deployable service.

Durable truth

Operator Sessions do not own launch state

SQLite stores applications, Phase Workspaces, Operator Sessions, messages, true Decision Records, Observations, Blockers, and activity. Gate Checks are recomputed from those sources.

Narrow intelligence

Pi is isolated; adapters expose facts

  • GitHub identity comes from `gh api`.
  • Pi receives only the supplied Operator Record and current Operator Session, with tools and project resources disabled.
  • Incomplete model output and adapter errors remain visible.
