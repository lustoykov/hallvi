Architecture · PR 7 · three snapshots

How the Pi boundary got simpler

PR 7 first made one large JSON reply strict. The final version keeps chat conversational and makes only the durable Decision machine-readable.

Before PR 7

Hand-parse everything

Pi was asked for JSON, but Server Guy repaired and filtered it by hand.

  • Invalid model data could disappear silently.
  • The stored reply could differ from what Pi tried to return.

PR 7 · version 1

Validate one big envelope

The first hardening pass rejected the entire reply unless all JSON was valid.

  • No silent dropping or truncation.
  • But human-facing text and machine data were unnecessarily coupled.

PR 7 · version 2 · final

Type only the machine action

Pi speaks normally and optionally calls one narrow typed tool for a durable Decision.

  • No Decision tool call means no Decision is recorded.
  • A bad tool call is rejected before it can be collected as a proposal.
  • Server Guy validates again and owns the database write.

The other half of PR 7 stays unchanged

HTTP request JSON → strict Zod request schema → typed command · malformed or oversized input → HTTP 400
